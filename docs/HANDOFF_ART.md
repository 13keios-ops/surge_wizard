> ### 🔴 반려된 것은 **화면**이지 **원화 화풍이 아니다**
> 사용자 말: **「마법사 원화 퀄에 비해 나머지가 다 떨어져서 별로다」**
>
> | | |
> |---|---|
> | **원화 화풍·품질** | ✅ **좋다. 이것이 기준(style reference)이다** |
> | **원화 규격(논리 칸)** | ⛔ 미달 — 308칸이라 화면에서 뭉개진다 |
> | **화면 전체** | ⛔ 반려 — 옆의 적·배경이 코드 도트다 |
>
> **마법사를 다시 뽑는 것은 「그림이 별로라서」가 아니라 「칸 밀도를 맞추려고」다.**

**원인은 화풍이 아니라 칸 밀도다.** 기획 창이 코드로 재현했다 (**칸 대 칸**):

| | 한 칸 | 캐릭터가 몇 칸 |
|---|---|---|
| 적·배경 (코드 도트, 48칸 격자 → 상자 142dp) | **2.96 dp** | 48칸 |
| 마법사 원화 (블록 2px → 512 캔버스 → 상자 142dp) | **0.383 dp** | **308칸** |
| | **7.7배** | |

> ⚠ **보고서와 첫 검토서의 「10.7배」는 단위가 다른 비교였다** —
> 코드의 한 *칸*(2.96)과 원화의 원본 *1픽셀*(0.277)을 견줬다.
> **원화의 한 칸은 원본 2px**이므로 같은 단위로는 **7.7배**다.
> 방향과 결론은 같고 **크기만 부풀려져 있었다.**

> **적과 배경이 코드 도트로 남아 있는 한 어떤 원화를 넣어도 화면은 통일되지 않는다.**
> 마법사를 다시 뽑아도 안 되고, 상자 크기를 조절해도 안 된다.
