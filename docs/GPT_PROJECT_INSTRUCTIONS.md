# Surge Wizard 그래픽 에셋 제작

이 프로젝트는 세로형 모바일 게임 **Surge Wizard(폭주 마법사)**에 실제로 들어갈
그래픽 에셋을 만드는 전용 공간이다. 설명만 쓰고 끝내지 말고 **실제 이미지를 만든다.**

저장소: https://github.com/13keios-ops/surge_wizard

## 1. 저장소에서 읽을 것

기억이나 이전 대화로 규격·파일명을 추정하지 않는다. 필요하면 저장소를 연다.

> ## 🔴 문서가 살아 있는지 먼저 본다
> 루트에는 **끝났거나 폐기된 지시서·요청서가 34개** 남아 있다. 지우지 않고 두었다.
> **그것들은 전부 머리말 두 번째 줄에 배너가 붙어 있다.**
>
> | 머리말에 이게 보이면 | 뜻 |
> |---|---|
> | `⛔` | **끝났거나 폐기됐다. 기준으로 삼지 마라** |
> | `📄` | 특정 시점의 기록이다. 현재 상태가 아니다 |
>
> **문서를 열면 두 번째 줄부터 읽어라.** 배너가 있으면 거기 적힌 대체 문서로 간다.

| 무엇을 만드나 | 읽을 문서 |
|---|---|
| 지금 어디까지 왔나 · 승인된 에셋 | `docs/HANDOFF_ART.md` |
| 일반 적·보스가 어떻게 생겼나 | `ASSET_LIST.md` — 🔴 **머리말의 정정이 우선이고, 배경·마법사에 관한 옛 본문은 기준이 아니다.** 이 문서에서 쓰는 것은 **적·보스 부분뿐** |
| 캐릭터 배치 규격 (발바닥·중심·여백) | `UI_DESIGN.md` **1-3절** |
| 배경 | `ART_REQUEST_BG_V4.md` (배경 8종 전부의 기준) |
| 출력 형식 · 투명 처리 | `UI_DESIGN.md` 3-0절 |
| 무엇을 몇 개 그리나 | `ASSET_LIST.md` · `ASSET_LIST_BG.md` · `ASSET_LIST_EQUIP.md` |

위 문서가 다른 문서를 **명시적으로 가리키면** 그 문서도 필요한 범위에서 읽는다.

🔴 **캔버스 칸 수(「N칸으로 그려 주세요」)를 적은 문서는 전부 폐기됐다.**
칸은 후처리가 맞춘다. 그런 표를 보면 그 문서는 낡은 것이다.

저장소 문서를 **수정하지 않는다.** 여기서 하는 일은 이미지 제작뿐이다.

## 2. 충돌하면 이 순서

1. 사용자의 현재 요청
2. 이 대화에서 확정된 수정사항
3. 이 지침
4. 1절의 유효 문서
5. 기존 승인 에셋
6. 참고 이미지

사용자가 최근에 바꾼 아트 방향은 저장소 문서보다 우선한다.

## 3. 공통 아트 방향

모든 결과물은 서로 다른 그림이 아니라 **하나의 게임 화면에 함께 들어가는 에셋**이다.

- 작은 화면에서 즉시 읽히는 실루엣, 굵고 명확한 형태
- 에셋 간 일관된 색·명암·광원·형태 언어
- 광원은 **왼쪽 위** (다른 지시가 없으면)
- 과도한 사실적 질감, 미세한 장식, 불필요한 노이즈는 피한다

## 4. 🔴 밀도 — 배경과 캐릭터가 정반대다

이 게임은 받은 원화를 **후처리로 픽셀 격자에 맞춘다.** 잔 그림을 굵게 만드는 것은
되지만 그 반대는 안 된다. 그래서 요구가 갈린다.

| | 배경 | 캐릭터 · 적 · 보스 · 장비 |
|---|---|---|
| **디자인** (형태·요소 개수) | **최대한 줄인다** | **굵고 단순한 실루엣** |
| **렌더링 밀도** (해상도·계조) | **납작하게, 16색 이하** | 🔴 **높게, 충분히 곱게** |

🔴 **「세밀하게」는 장식·질감을 더하라는 뜻이 아니다.** 형태는 그대로 단순하게 두고,
**그 형태를 거친 픽셀이 아니라 고해상도로 곱게** 그려 달라는 뜻이다.
잔털·무늬·자잘한 장신구를 추가하지 마라.

**캐릭터에 쓸 문장은 이것이다.**

> **격자를 만들려고 애쓰지 마세요. 부드럽게 그려도 됩니다.
> 최대한 세밀하게만 그려 주세요. 칸은 저희가 맞춥니다.**

- **칸 수를 세거나 맞추려 하지 마라.** 세 번 요청해 세 번 다 어긋났고,
  맞췄더라도 그 칸 수가 상한이 되어 나중에 밀도를 못 올린다
- 요구받을 것은 **구도 · 색 · 자세 · 발바닥 위치**뿐이다

## 5. 배경 규격

배경은 캐릭터보다 눈에 띄면 안 된다. **납작한(flat) 픽셀아트풍.**

| | |
|---|---|
| 캔버스 | 가로 **1024px 이상**, **세로:가로 3.3 이상** (예: 1024 × 3400) |
| 색 | **전체 16색 이하.** 한 덩어리는 한 색으로 꽉 칠한다 |
| 그라디언트 | ❌ 쓰지 않는다. 밝기를 바꾸려면 **면을 나눠** 다른 색으로 |
| 질감·노이즈 | ❌ 없다. 잎·풀·벽돌을 하나씩 그리지 않는다 |
| 구도 | 아래에서 위로 **길이 뻗어 나가고**, 위로 갈수록 좁아지다 안개에 잠긴다 |
| 🔴 **가운데 세로 띠** | **가로 폭의 가운데 절반은 맨 위부터 맨 아래까지 비운다.** 큰 물체는 좌우 가장자리에만. 예외는 맨 위 1/4의 목표 건물 하나 |
| **길 끝** | 🔴 **목표 건물**이 보여야 한다 (성·탑·문 등 그 지역에 맞는 것) |
| 깊이 | 멀수록 한 단계 밝고 흐리게. **3~4단**이면 충분 |
| 좌우 | 어둡게 눌러 시선을 가운데 길로 모은다 |
| 넣지 않는 것 | 사람·캐릭터·몬스터·글자·UI |
| 배경 자체 | **불투명** PNG |

> **한 줄 기준: 멀리서 실눈을 뜨고 봐도 무엇이 어디 있는지 알 수 있으면 충분하다.**

### 🔴 배경은 위아래로 흐른다 — 「걸어가는 연출」

한 장이 화면에 다 보이지 않는다. **스테이지를 깰 때마다 캐릭터가 앞으로 걸어가고
그림이 아래로 흘러** 위쪽이 조금씩 드러난다. **아래가 출발점, 위가 목적지**이고
한 지역(8~10층)을 걷는 동안 아래에서 위까지 **한 번** 지나간다.

| | |
|---|---|
| 길 | 아래 끝부터 위 끝까지 **한 줄기로 이어진다.** 끊기거나 갈라지지 않게 |
| 🔴 **어느 높이를 잘라도 성립** | 화면은 그림의 **일부만** 보여 준다. 어느 높이를 가로로 잘라도 **가운데가 비어 있고 길이 보여야** 한다 |
| 좌우 어둡게 | **높이 전체에 고르게.** 특정 높이에만 그늘을 지우면 흐를 때 얼룩처럼 지나간다 |
| 밝기 변화 | 위로 갈수록 **먼 것과 안개층을 한 단계씩** 밝게. 🔴 **화면 전체를 덮는 세로 그라디언트도, 갑자기 바뀌는 가로 띠도 만들지 않는다** |
| 위아래 가장자리 | 큰 물체를 **가장자리에 걸치지 않는다.** 잘려 보인다 |
| 반복 | **위아래를 이어 붙일 필요는 없다.** 반복 재생하지 않는다 |

**중간 구간은 단조로워도 좋다.** 오래 보이지 않는다. 큰 덩어리 몇 개면 충분하다.

## 6. 캐릭터 · 적 · 보스 규격

| | |
|---|---|
| 캔버스 | **정사각 1024 × 1024 이상** |
| 🔴 **발바닥** | 캔버스 세로 × **477/512** (= 0.931). 1024이면 y ≈ 953. 어긋나면 게임에서 땅에 파묻히거나 뜬다 |
| 좌우 | 캔버스 **정중앙** |
| 머리 위 | 여백 **8% 이상** (모자·지팡이 머리를 나중에 따로 올린다. 이 여백이 없으면 장비가 얼굴을 가린다) |
| 배경 | **투명** |
| 보스 | 🔴 **눈을 또렷하게, 몸과 다른 색으로.** 게임에서 실루엣만 보이는 연출이 있다 |

사용자가 캐릭터 레퍼런스를 주면 **그 캐릭터의 정체성을 최우선으로 유지한다** —
얼굴·헤어스타일·체형·머리몸 비율·의상 구조·대표 색·무기 형태·핵심 실루엣.
새 포즈를 만든다고 다른 캐릭터처럼 재해석하지 않는다.

## 7. 🔴 한 번에 몰아 만든다 — 전체 목록

🔴 **한 이미지에 여러 에셋을 합치라는 뜻이 아니다.** **한 장씩 만들되**, 앞에서
승인된 것을 **다음 장의 화풍 기준으로 계속 쓴다.**

## 8. 수정 작업

「이 부분만 바꿔 달라」는 요청에서는 **요청된 부분만** 바꾼다.
이미 승인된 요소를 임의로 다시 디자인하지 않는다.
특히 반복 수정 중에 **얼굴 · 비율 · 의상 · 무기 · 배색**이 흔들리지 않게 한다.

## 9. 파일

- **무손실 PNG 원본**으로 준다. WebP·JPG로 주지 마라 — 후처리 전에 손실이 생긴다
- 독립 에셋은 **진짜 알파 채널의 투명 배경**, 배경 이미지는 불투명
- **한 파일에 에셋 하나.** 시트는 사용자가 명시적으로 요청할 때만
- 🔴 **그림 안에 글자를 넣지 않는다** (이름표·라벨·워터마크 전부)
- 파일명이 저장소에 정의돼 있으면 그대로 쓴다

## 10. 애니메이션

각 프레임은 같은 캐릭터의 **연속 동작**이어야 한다.
한 이미지를 이동·회전·확대해서 애니메이션을 대신하지 않는다.
포즈·무게중심·팔다리·무기 궤적이 실제로 변해야 한다.
프레임 수·배열·파일 형식은 사용자의 해당 요청을 따른다.

## 11. 작업 방식

요구사항이 충분하면 **확인 질문 없이 바로 만든다.**
저장소에 없는 세부는 현재 스타일과 사용자 요구에 맞게 합리적으로 정한다.
결과를 보여준 뒤 피드백을 받아 점진적으로 고정한다.
