> **배경 제거 → 알파 경계 크롭 후 512×512 정규화 → 알파 250 이상 255 스냅 → WebP.**
> **알파 이진화(0/255)는 하지 않는다.** 반투명·glow를 허용한다

> ## 🔴 2026-09-08 — 후처리에 **「격자화」**가 한 단계 늘었다 (검토 32 승인)
>
> ```
> 배경 제거 → 알파 경계 크롭·정규화 → 🔴 격자화 → 알파 255 스냅 → WebP
> ```
>
> **`tool/gridize.py`** — 면적 평균으로 **규격 칸 수까지 줄이고 정수배로 최근접 확대**한다.
> 그것뿐이다. **팔레트 근사·포스터라이즈·외곽선 추가·알파 이진화는 여전히 안 한다.**
>
> **왜**: 생성기가 「칸 수」를 못 지킨다. 마법사 46칸을 **두 번** 요청했는데
> **56.4 → 56.5칸**(0.1칸 움직였다), 배경 1024를 두 번 요청했는데 **두 번 다 841**.
> **숫자를 더 세게 적어서 되는 문제가 아니다.**
>
> **왜 해도 되나**: 받은 그림은 언제나 **필요한 것보다 잘다.**
> **잔 것을 굵게 만드는 것은 정보를 버리는 방향이라 되고, 그 반대는 안 된다.**
> 걸어 보니 네 장 전부 **격자 적합 0.00** — Phase 1.5 합격 원화와 같은 값이다.
>
> 🔴 **그래서 요청서는 「칸 수」를 「상한」으로 적는다** —
> 「46칸으로」가 아니라 **「46칸보다 잘게」**, 캔버스도 **「1024 이상」**.
> 원화가 규격보다 **굵게** 오면 격자화로 못 고친다..

## 폴더가 두 개인 이유

| 폴더 | 무엇 | 게임이 읽나 |
|---|---|---|
| **`art_raw/`** | 생성기가 준 **원본 PNG** + 메타데이터 | ❌ |
| **`assets/art/`** | 후처리를 끝낸 **게임용 WebP** | ✅ |

원본을 남겨 두는 이유는 **후처리 규칙이 바뀌면 다시 구워야** 하기 때문입니다.
원본을 버리면 그때 46장을 전부 다시 뽑아야 합니다.

> ⚠ 나중에 파일이 많아져 저장소가 무거워지면 `art_raw/`만 따로 빼냅니다.
> 그때까지는 여기 두는 것이 편합니다.

> ## 🔴 칸 크기는 **`tool/measure_grid.py` 로 잰다** (2026-09-08 확정, 검토 32)
>
> ```
> python tool/measure_grid.py <파일...>
> ```
>
> **후보 칸 크기 p 마다 「블록 안쪽 색의 표준편차」를 재서 극소점을 찾는다.**
> 격자가 완벽하면 블록 안이 단색이라 **표준편차가 정확히 0** 이다.
>
> **먼저 검산하라** — 합격이 확인된 원화로 방법이 살아 있는지 본다:
> ```
> python tool/measure_grid.py art_raw/phase1_5_assets/wizard_back.png
> → p=7 에서 0.00 이 나와야 한다
> ```
>
> ### ❌ 이 두 가지로는 재지 마라
> | 방법 | 왜 안 되나 |
> |---|---|
> | **런 최빈값** | 안티에일리어싱이 조금만 있어도 **1px 런이 82~96%** 로 무너져 아무것도 못 말한다 |
> | **엣지 자기상관** | **없는 격자를 있다고 한다.** 격자가 전혀 없는 그림에서 상관 0.52로 「9~10px」이 나왔다 |
>
> **판정**: 극소점의 표준편차가 **0에 가까울수록 또렷**하다. **극소점이 아예 없으면
> 격자가 없는 것**(부드럽게 칠한 그림)이고 **반려**다.
> 화면 한 칸이 **1.9 ~ 2.1dp** 를 벗어나도 반려다 (`UI_DESIGN.md` 1-2-b).

## 장비(지팡이·모자·로브) 실측 절차 — 2026-09-04 신설

기준값은 전부 `ASSET_LIST_EQUIP.md` 2절에 있다.

> 이 절차가 없어서 앞선 창이 매번 다시 궁리했다. 그림을 보기 전에 **먼저 재라.**
> 규격에서 떨어진 것은 눈으로 볼 필요가 없다 (토큰 절약).

### 1단계 — 눈으로 보기 전에 숫자부터 낸다

알파 채널이 0이 아닌 화소만 본다. 15종을 한 번에 표로 뽑는다.

| 재는 값 | 어떻게 | 합격선 |
|---|---|---|
| **길이** | 알파>0인 화소의 세로 범위 | 캐릭터 신장 599px의 **108~112%** = **647~671px** |
| **헤드가 내려온 깊이** | 위에서부터 **가로 폭이 몸통 굵기로 좁아지는 첫 줄** ÷ 전체 길이 | **30% 이내** |
| **몸통 폭** | 아래 40~90% 구간에서 각 줄의 알파 폭을 재 **중앙값** | 등급별 **30~42px** |
| **막힌 덩어리** | 헤드 구간에서 **가로로 끊기지 않고 이어진 알파 구간**의 최대 길이 | 등급별 **70~150px** |
| **고유색 수** | RGB 서로 다른 값의 개수 | **수천 개 이상**. 24~32개면 **강제 양자화 사고** |
| **알파 계조** | 0도 255도 아닌 알파값의 비율 | 0%면 **알파 이진화 사고** |

- **「막힌 덩어리」와 「헤드 폭」을 헷갈리지 마라.** 궤도·별처럼 틈이 많은 장식은
  넓어도 얼굴을 안 가린다. 가리는 것은 **연속된 불투명 덩어리**뿐이다
  (v1 전설 지팡이: 폭 352px이지만 최대 덩어리 138px < 얼굴 169px → 합격)

### 2단계 — 캐릭터에 실제로 합성해 본다

**숫자만으로 판정하지 마라.** `wizard_body.png` 위에 지팡이를
`UI_DESIGN.md`의 배율(**1.10**)과 앵커로 올려 합성한 그림을 만든다.

- **얼굴(피부만) 169px 폭 영역에 지팡이 알파가 겹치는가** → 겹치면 불합격
- **몸통 영역이 얼마나 덮이는가**

### 3단계 — 그때 비로소 본다

합성본을 **가로 480px로 줄여** 그것만 연다. 15종을 한 장의 대비표로 붙여
