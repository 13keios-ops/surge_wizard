## 6. ★ 지시서를 벗어난 것

| 무엇을 | 왜 | 되돌릴 수 있나 |
|---|---|---|
| **`kDifficultyScales` 의 `expMul` 을 1.6/2.5 → 1.5/2.0 으로 고쳤다** | 지시서 1-B가 **하드 ×1.5 · 데스 ×2.0**을 요구하는데, `constants.dart` 에 **이미 `expMul` 이 1.6 / 2.5 로 있었다**(WORK_ORDER_PROGRESSION 2-C의 임시값, 「지급은 아직 안 붙였다」는 주석과 함께). **새 상수를 따로 만들면 같은 뜻의 값이 두 곳에 생겨 반드시 어긋난다.** 아무 데서도 안 쓰이던 값이라 밸런스에 영향이 없다 | 예 (한 줄) |
| **`Enemy` 에 `variantId` 칸을 더했다** | 변종 ×1.5를 판정하려면 「이 적이 어느 변종인가」가 필요한데, `buildEnemy` 가 이름 앞머리만 붙이고 변종 정체를 버리고 있었다. **JSON에서는 안 읽는다** — 조립 때만 채워지고 기본값은 「기본 변종」이다 | 예 |
| **`tool/measure_condition.dart` 두 줄을 고쳤다** | 지시서는 `tool/` 을 건드리지 말라고 했지만, 이 파일이 `GameData(...)` 와 `Region(...)` 을 **직접 생성**하고 있어 새 칸이 생기면 **컴파일이 안 된다.** 고친 것은 `circleSlots: data.circleSlots` · `exp: r.exp` **두 줄뿐**이고 둘 다 **원본 값을 그대로 넘긴다** — 측정 결과는 한 자리도 안 바뀐다 | 예 |
| **기존 테스트 4개 파일의 생성자 호출을 고쳤다** | `GameData(...)`·`ResultScreen(...)` 에 새 인자가 생겨 컴파일이 깨졌다. **단언(expect)은 한 줄도 안 고쳤다** | 예 |
| **결과 화면에서 경험치를 「영구 강화 안내 문구」 아래에 놓았다** | 위에 놓으니 「타이틀의 "영구 강화"에서 쓸 수 있다」가 **경험치에 붙은 말처럼** 읽혔다. 3-A가 금지한 것은 **그 문구를 고치는 것**이라 문구는 그대로 두고 순서만 바꿨다 | 예 |

## 7. ★ 판단이 필요한 것

1. **`hard`/`death` 경험치 배율의 최종 확인** — 위 6절대로 **`GROWTH.md` 1.3절
   (1.5 / 2.0)** 을 채택했다. 옛 `expMul`(1.6 / 2.5)을 살릴 이유가 있으면 알려 달라.
   지금은 `GROWTH.md` 가 최신(2026-09-05)이고 지시서도 1.5/2.0을 지정했으므로
   문서 쪽이 맞다고 판단했다.

2. **변종 경험치 배수의 범위** — 「변종 ×1.5」를 **「기본」이 아닌 변종 전부**
   (굶주린·부패한·얼어붙은·그림자·고대의)에 적용했다. `GROWTH.md` 1.3절이
   「변종 (「고대의」 등)」이라고만 적어 「고대의만」으로 읽을 여지가 있다.
   - **지금 방식(전부)**: 1지역부터 변종이 섞여 4-A 검산보다 실제 획득이 조금 많다
     (실측 1지역 Ⅰ 3층에서 175 → 188). 「유저는 권장 레벨보다 조금 위」라는
     `GROWTH.md` 1.4절 완충 설명과 방향이 같다
   - **「고대의만」으로 바꾸면**: 하드·데스에서만 변종 배수가 붙는다
   - **4-A 검산은 어느 쪽이든 안 흔들린다** (검산은 변종 없는 조건이다)

3. **만렙에서 남은 경험치를 버린다** — 레벨 99에 닿으면 `exp` 를 0으로 두고
   그 뒤로는 쌓지 않는다. 나중에 「만렙 뒤 경험치를 다른 재화로 환산」할 계획이
   있으면 지금 방식을 바꿔야 한다.
