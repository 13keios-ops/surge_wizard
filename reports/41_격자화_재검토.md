# 41. 격자화를 다시 본다 — **우리가 세부를 6배 깎고 있다**

작성: 2026-09-13, 기획 창. 계기: 사용자가 저해상도 샘플을 보고 **「조악하다」**고 반려.

> 🔴 **이것은 검토 32의 결정(격자화 도입)을 뒤집자는 제안이다. 사용자 승인이 필요하다.**

## 어떻게 여기까지 왔나

1. GPT 38종을 게임 크기로 줄이니 **자세한 것이 전부 사라졌다** (검토 3차)
2. 그러면 **애초에 게임 해상도로 그리게 하자** → 시험 → **조악해서 반려**
3. 사용자: 「차라리 처음 그림을 리사이징만 해서 넣자. 딸깍 다이스는 어떤지 봐라」
4. **그래서 참고 게임을 실측했다. 답이 거기 있었다.**

## 참고 게임 실측 (`refs/dicero/16_전투화면_전체구도_최종참고.png`, 1080×2400)

적 하나를 화면에서 잘라(160×170) 쟀다.

| 무엇 | 값 | 뜻 |
|---|---|---|
| 같은 색이 이어지는 길이 | **1px 53% · 2px 20%** | **지배적인 블록 크기가 없다 = 격자를 강제하지 않는다** |
| 고유 색 (캐릭터 8688px) | **105개** | 팔레트가 좁다 (픽셀아트 규율) |
| 줄였다 늘렸을 때 오차 | N이 커질수록 **매끄럽게만** 감소 | **작은 원본을 확대한 것이 아니다** |
| 가장자리 급변 비율 | **0.85** | 또렷하다. 흐린 경사가 거의 없다 |

**→ 화면 크기에 가까운 해상도로 직접 그린 그림을, 격자화 없이 그대로 쓴다.**

### 🔴 결정적인 숫자

| | 화면 표시 크기 | 실제 정보량 | 거칠기 |
|---|---|---|---|
| 참고 게임 적 | 160px | **160** | 1배 |
| **우리 적** | 228 물리px (76dp × 3배 화면) | **37칸** | 🔴 **6.2배 거칠다** |

**원화가 모자란 것이 아니다. 격자화가 버리고 있다.**
우리 고블린 원화는 1024px인데 화면에는 37칸어치만 나간다.

## 그림 (`reports/img/compare/gridize_vs_resize.png`)

같은 화면 크기(228 물리px)로 셋을 나란히 놨다 — 참고 게임 · 격자화(지금) · 원화 축소(제안).
**격자화한 것만 덩어리로 보인다.**

## 제안 — 캐릭터에서 격자화를 뺀다

| | 지금 | 제안 |
|---|---|---|
| 원화 → 게임 | `gridize` 로 **N칸에 강제로 찍는다** | **그냥 줄인다** (화면 물리 픽셀에 맞춰) |
| 일관성 보증 | 칸 수가 같으니 자동 | 🔴 **미술 지시와 측정으로 지킨다** — 참고 게임이 하는 방식 |
| 밀도 밴드 1.55~1.75dp | 한 칸이 몇 dp인가 | **의미가 없어진다** (칸이 없다) |

### 잃는 것을 정직하게

- **검토 32의 근거가 사라진다.** 그때 격자화를 넣은 이유는 **생성기가 칸 수를 못 맞춰서**였다.
  하지만 참고 게임은 애초에 칸을 세지 않는다. **문제를 잘못 잡았던 것이다**
- **일관성 보증이 자동에서 수동으로** 바뀐다. 대신 **팔레트 폭**(참고 게임 105색)을
  새 기준으로 삼아 잴 수 있다
- **배경은 별개다.** 배경은 이미 2px 블록이고 캐릭터와 다른 문제다

### 얻는 것

- 세부가 **6배** 살아난다. 38종이 회색 덩어리가 되던 문제의 **직접적인 원인이 사라진다**
- 원화를 크게 받아 두는 지금 방침이 그대로 유효하다 (오히려 더 잘 쓰인다)
- 「게임 해상도로 그려라」 같은 어려운 요구를 생성기에 하지 않아도 된다
