## 1. 독립 재현 — 3.4절 표 문제는 사실이다

기획 창이 파이썬으로 **3d6 216가지를 전부 열거해** 두 규칙으로 계산했다
(트리플 > 스트레이트 > 뱀눈 > 페어 우선순위 그대로).

| 계산 조건 | 보통 (DC10) | 전력 (DC13) |
|---|---|---|
| **뱀눈 = 폭주 확정** (3.5절·코드) | 38.9 / 33.3 / 18.1 / **9.7** | 16.7 / 22.2 / 33.3 / **27.8** |
| **뱀눈 = 그냥 페어** | 38.9 / 36.1 / 22.2 / **2.8** | 16.7 / 22.2 / 36.1 / **25.0** |
| **`GAME_DESIGN.md` 3.4절 표** | 38.9 / 36.1 / 22.2 / **2.8** | 16.7 / 22.2 / 36.1 / **25.0** |

> **3.4절 표는 「뱀눈 = 그냥 페어」 계산과 여덟 값이 전부 일치한다.**
> 뱀눈(1이 2개, 트리플 제외) = **15/216 = 6.94%** 가 통째로 빠져 있다.

**보고서가 옳다. 코드가 옳고, 표가 3.5절을 반영하지 않은 계산이다.**

`dart run tool/measure.dart`도 직접 돌려 **전투당 2.40 / 2.42 굴림**이
재현되는 것을 확인했다.

### 원칙 2(「완전 실패는 드물어야 한다」)는 깨지지 않는다

표가 바뀌면 보통 실패가 2.8% → 9.7%가 된다. 그래도 원칙은 지켜진다:

- **실제 플레이(모드 C) 실패율은 보통 1.4% / 전력 12.2%다.** 리롤과 마력 축적이
  흡수한다. 9.7%는 「리롤도 유물도 없는 이론값」이다
- 게다가 **뱀눈 실패는 반드시 폭주로 이어진다.** 원칙 3(「실패는 콘텐츠다」)에
  비추면 이쪽이 오히려 설계 의도에 맞다

→ **사용자 승인을 받은 뒤 `GAME_DESIGN.md` 3.4절을 갱신한다.**

## 3. ⚠ 7-2·7-3은 지금 고치지 않는다 — 측정 조건이 우리 게임이 아니다

**이것이 이 검토의 핵심이다.**

보고서는 「9굴림 → 2.4굴림」·「5~8턴 → 1.5턴」을 정확히 쟀다. 그런데
**무엇을 재고 있었는지**를 함께 봐야 한다.

| 측정이 돌아간 구조 | 우리가 만들 구조 |
|---|---|
| 10층 단선 | 지역 12 · 스테이지 100 · 층 3~10 |
| **지역 배율 없음** | **×1.00 → ×5.00** (`ENEMIES.md` 6절) |
| 보스 HP 88~95 (옛 4종) | **40 → 480** (12종) |
| 변종 없음 | 6변종, 종반 「고대의」 25% (HP ×1.5) |
| 플레이어 성장 없음 | 레벨 99 · 패시브 100노드 · 장비 6슬롯 |

**후반 전투를 거칠게 가늠하면** (지역 12 일반 적 = tier5 45 × 배율 5.0 = **225**,
보스 **480**, 플레이어 9서클 22 × 전력 3배 ≈ 66):

```
후반 일반 전투 ≈ 3~4턴 · 후반 보스 ≈ 7턴   (지금 측정치의 2~4배)
```

> **2.4굴림도 1.5턴도 최종값이 아니다.** 지금 각인 수치표나 층수표를 이 값으로
> 고치면 **진행 구조가 들어온 뒤 다시 고쳐야 한다. 두 번 일하게 된다.**

### 대신 지금 한 것 — 문서에 경고를 박았다

수치는 그대로 두되, **아무도 그 전제 위에 새로 쌓지 못하게** 표시했다.

**7-2의 네 선택지(A 전투 길이 / B 각인 수치 / C 적립 상한 / D 문서 갱신)는

### 「엔진 전수계산」 줄을 스스로 추가한 것

지시서는 **「A 모드가 3.4절 표와 맞는지 보라」**고만 했다. 그런데 A 모드에도
주문 DC 보정·판정 보너스·주사위 추가가 섞여 있어 **「측정이 틀렸나 표가 틀렸나」를
가릴 수 없다.** 구현 창이 그걸 알아채고

- **엔진을 216가지 전수로 돌린 이론값** 줄과
- **조건을 완전히 맞춘 「A 보정0」** 줄

을 스스로 만들어 **원인을 표로 특정**했다. **지시서의 검사 설계가 부족했던 것을
메운 것이다.** 이게 없었으면 「표가 틀렸다」는 결론에 도달하지 못했다.

## 6. 잘한 점

1. **판정을 두 단계로 나눠 적었다** — 「측정 코드는 옳다」를 먼저 세우고,
   그 위에서 「어긋나는 쪽은 표다」로 갔다. 순서가 정확하다
2. **원인을 6.94%p라는 숫자 하나로 특정**하고, 뱀눈을 빼면 표가 소수점까지
   재현된다는 것까지 보였다. 추측이 아니라 증명이다
3. **밸런스를 하나도 안 건드렸다.** `simulate.dart` 기준선이 개정 전과 같은 값을
   내는 것까지 확인해 「계측을 넣었지만 게임은 안 변했다」를 증명했다
4. 두 시드 비교로 **결론에 쓰는 값이 시드 간 0.3 이하**임을 보였다
